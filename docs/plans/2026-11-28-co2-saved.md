# The CO2 a shared ride saves Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a small, informative "CO₂ saved" card on a ride, a booked seat,
the driver's ride and My profile, counted as one car not driven per
completed booking, with each member's own record kept for good.

**Architecture:** The counting is pure functions in a new domain folder,
`packages/domain/src/co2/`. One operator setting, `co2_grams_per_car_km`,
gives the grams per car kilometre. A booking stores its grams in a new
column, `bookings.co2_grams`, at the moment it becomes completed; before
that, the API estimates the figure from the part's road distance. Totals
are sums over completed bookings, plus a small `co2_carried` row per
member that the 3-year anonymisation fills, so totals never drop. The
app shows one shared component, `Co2Card`, built from `Card` and an
unfolding `Row`.

**Tech Stack:** TypeScript domain package (Vitest), Hono, zod and Drizzle
(API, PostgreSQL 18), Expo with React Native Web (app, Jest and RNTL 14),
React with Vite (console), Playwright journeys.

**Spec:** [spec 34](../specs/2026-11-28-co2-saved.md), with
[ADR 0054](../decisions/0054-estimate-co2-saved-as-one-car-not-driven.md)
(Accepted).

## Global Constraints

- One completed booking is one car, whatever its seats (R34.1).
- Grams = road metres of the part × setting ÷ 1000, rounded to whole grams
  (`Math.round`); kept on the booking from completion on (R34.2).
- Only `completed` bookings count toward totals; leaving `completed` sets
  `co2_grams` back to null (R34.3).
- Shown in whole kilograms, rounded down; under 1 000 g, or with the
  setting at 0, nothing shows: no card, no group, no About section (R34.7).
- Setting `co2_grams_per_car_km`: group `co2`, unit `g_per_km`, default
  150, min 0, max 300, step 1 (ADR 0054).
- Every text says "estimated" or "about" and "compared with driving
  alone", and links to `/about#co2` (R34.4). None says "carbon neutral",
  "climate neutral", "zero emissions", "green", "eco-friendly", offsets
  or credits, and none mentions money, prices, payments or fees (R34.5).
- "CO₂" with the subscript only in Nunito text, never in a Fredoka title;
  screen readers get `co2.spoken` ("CO2 saved, about 58 kilograms,
  estimated").
- A member's own figures go to them alone; the operator sees weekly sums
  (R34.6). Nothing goes to Google Analytics, emails, notifications,
  tickets or public profiles.
- On a laptop the card is never in a side column (R34.8).
- Every text in `en.ts` and `is.ts`, with the spec's wording (section 8).
  Distances are written by `formatDistance` and kilograms by
  `formatCount`, so the spec's `{km} km` is the placeholder `{distance}`
  (my call: one way of writing distances in the app).
- The card has no colour, badge or puffin of its own (3.4, item 3) and
  uses only design-system tokens and parts.
- Migrations: check `packages/db/migrations` for the next number first
  (0065 at the time of writing); other threads add migrations too.
- Two deploys are not needed: older code ignores the new column, the new
  table and the new setting key, and reads only the metric keys it knows
  (`addWeekMetrics`). Say so in each PR.
- No new runtime dependency (Lucide already has `Leaf`).

## Review Focus

1. A booking with two seats, or a driver with two bookings from the same
   two people, still counts one car per booking, never per seat.
2. The setting changed after a booking completed leaves its grams alone,
   and the setting set to 0 hides every figure, stored ones included,
   until it is set again.
3. A role line on Profile with under 1 kg is left out ("As a passenger:
   0 kg" never shows), while the total can still show.
4. The total on Profile is the same the hour before and the hour after a
   trip is made anonymous, for the passenger and for the driver, and an
   erased passenger's bookings still count for their driver.
5. The laptop side columns of the booked seat and the driver's ride hold
   exactly what they held, and the card never pushes them past 720 high.

Each line has its test in the task that owns it: 1 in Tasks 1 and 4, 2 in
Tasks 3 and 4, 3 in Task 9, 4 in Task 11, 5 in Task 10.
